## 引论和服务

数据链路层解决的是：**相邻节点之间如何把网络层数据报封装成帧并传输。**

**考试核心**

|概念|必背|
|---|---|
|节点|主机、路由器等设备|
|链路|相邻节点之间的通信通道|
|帧 frame|数据链路层 PDU|
|网卡 NIC|数据链路层功能通常由网卡实现|
|通信范围|相邻节点到相邻节点|

**数据链路层服务**

1. **成帧**：把网络层数据报封装成帧。
2. **链路访问**：共享链路时决定谁能发送。
3. **差错检测和纠正**：如 CRC。
4. **可靠交付**：某些链路层协议可在相邻节点间提供可靠传输。
5. **流量控制**：防止接收方处理不过来。
6. **半双工/全双工通信**。

## 差错检测和纠正

**一句话说明**  
差错检测和纠正解决的是：**接收方如何发现甚至纠正链路传输中的比特错误。**

**1. 基本概念**

发送方发送：

```
数据 D + 差错检测码 EDC
```

接收方检查：

```
收到的数据和 EDC 是否一致
```

常见方法：

- 奇偶校验
- 校验和
- CRC 循环冗余检测

链路层最常考：**CRC**。

**2. CRC 核心思想**

CRC 把比特串看成二进制多项式，使用生成多项式 `G` 做模 2 除法。

考试不用讲多项式，记这个：

> 发送方把数据 D 后面补 r 个 0，用生成多项式 G 做模 2 除法，得到 r 位余数 R，将 D 和 R 一起发送。接收方用同一个 G 去除收到的比特串，若余数为 0，则认为未检测到差错。

其中：

```
r = G 的位数 - 1
```

**3. CRC 计算步骤**

给：

```
D = 数据比特串
G = 生成多项式比特串
```

步骤：

1. 计算 `r = G位数 - 1`。
2. 在 D 后面补 `r` 个 0，得到 `D × 2^r`。
3. 用 G 对补 0 后的比特串做**模 2 除法**。
4. 得到 r 位余数 R。
5. 发送比特串为：

```
D + R
```

**模 2 除法规则**

```
减法不借位
加法不进位
本质就是异或 XOR
```

也就是：

```
1 XOR 1 = 0
1 XOR 0 = 1
0 XOR 1 = 1
0 XOR 0 = 0
```

**4. 例题**

给：

```
D = 101001
G = 1101
```

求 CRC 余数 R 和发送比特串。

第一步：

```
G 位数 = 4
r = 3
```

D 后补 3 个 0：

```
101001000
```

用 `1101` 做模 2 除法，余数为：

```
R = 001
```

所以发送：

```
101001001
```

这个例子是课件里的典型结果，要记住过程形式。

**5. 易错点**

1. `r = G位数 - 1`。
2. D 后面补的是 r 个 0。
3. CRC 除法是 XOR，不是普通减法。
4. 余数必须补足 r 位，不够前面补 0。
5. 发送的是 `D + R`，不是 `D + 0`。
6. 接收方整串除以 G，余数为 0 表示通过

## 多点访问协议

**1. 为什么需要多点访问协议**

在共享信道中，如果多个节点同时发送，会发生：

```
碰撞 collision
```

碰撞会导致帧损坏，需要重传，所以要有 MAC 协议协调发送。

**2. 多点访问协议三类**

| 类型   | 思想              | 例子                         |
| ---- | --------------- | -------------------------- |
| 信道划分 | 把信道资源固定分给用户     | TDMA、FDMA、CDMA             |
| 随机访问 | 节点需要时随机发送，碰撞后恢复 | ALOHA、CSMA、CSMA/CD、CSMA/CA |
| 轮流协议 | 节点按顺序获得发送机会     | 轮询、令牌传递                    |

**3. CSMA**

CSMA：Carrier Sense Multiple Access，载波侦听多路访问。

核心思想：

> 发送前先侦听信道，如果信道空闲就发送；如果忙，则等待。

口诀：

```
先听后说
```

但由于传播时延，两个节点可能都以为信道空闲而同时发送，所以仍可能碰撞。

**4. CSMA/CD**

CSMA/CD：载波侦听多路访问 / 碰撞检测。  
传统有线以太网使用。

流程：

```
发送前侦听
→ 空闲则发送
→ 发送过程中继续检测碰撞
→ 若检测到碰撞，立即停止发送并发送 jam 信号
→ 随机退避后重传
```

关键词：

- 先听后说
- 边说边听
- 碰撞检测
- jam 信号
- 二进制指数退避

**5. 二进制指数退避**

发生第 `n` 次碰撞后，随机选择：

```
K ∈ {0, 1, ..., 2^n - 1}
```

等待：

```
K × 512 bit time
```

如果题目问第 5 次碰撞后选择 `K=4` 的概率：

```
K 可选 0 ~ 31，共 32 个
P = 1/32
```

**6. CSMA/CD vs CSMA/CA**

| 协议      | 场景         | 核心   |
| ------- | ---------- | ---- |
| CSMA/CD | 有线以太网      | 碰撞检测 |
| CSMA/CA | 无线局域网 WiFi | 碰撞避免 |

无线中难以检测碰撞，所以采用避免机制，而不是检测。

**易错点**

1. CSMA 仍可能碰撞，因为传播时延。
2. CSMA/CD 是有线以太网经典机制。
3. CSMA/CA 是无线 WiFi 常用机制。
4. 第 n 次碰撞后 K 的选择范围是 `0 ~ 2^n - 1`。
5. `512 bit time` 不是 512 秒，要结合链路速率计算。

## addressing 与 ARP

#### **1. MAC 地址**

MAC 地址也叫物理地址、链路层地址。

特点：

- 长度：48 bit
- 常写成 6 个十六进制数：
    
    ```
    1A-2B-3C-4D-5E-6F
    ```
    
- 通常固化在网卡中
- 用于同一链路/局域网内帧传输

#### **2. IP 地址 vs MAC 地址**

| 比较项     | IP 地址          | MAC 地址      |
| ------- | -------------- | ----------- |
| 层次      | 网络层            | 数据链路层       |
| 长度      | IPv4 32 bit    | 48 bit      |
| 作用      | 标识主机/接口在网络中的位置 | 标识链路层接口     |
| 结构      | 层次化，便于路由       | 扁平化         |
| 是否随网络变化 | 主机换网络通常会变      | 网卡 MAC 通常不变 |
| 用途      | 跨网络寻址和路由       | 同一链路内帧转发    |

#### **3. ARP**

ARP：Address Resolution Protocol，地址解析协议。

作用：

```
IP 地址 → MAC 地址
```

ARP 表项：

```
IP 地址，MAC 地址，TTL
```

#### **4. ARP 工作过程**

同一局域网内，主机 A 要给 B 发帧，已知 B 的 IP，但不知道 B 的 MAC。

流程：

```
A 查询自己的 ARP 表
→ 若没有 B 的 MAC
→ A 广播 ARP 请求：谁拥有这个 IP？
→ B 收到后发现目标 IP 是自己
→ B 单播 ARP 响应：我的 MAC 是 xx
→ A 更新 ARP 表
→ A 用 B 的 MAC 封装帧并发送
```

**重点：请求广播，响应单播**

|报文|方式|原因|
|---|---|---|
|ARP 请求|广播|发送方不知道目标 MAC，只能问整个局域网|
|ARP 响应|单播|目标已经知道请求方 MAC，可直接回复|

#### **5. 跨网段通信**

如果目的主机不在同一子网：

```
源主机不会 ARP 目的主机的 MAC
而是 ARP 默认网关/下一跳路由器接口的 MAC
```

关键：

```
IP 源地址和目的地址：端到端通常不变
MAC 源地址和目的地址：每一跳都会变化
```

例子：

```
A → 路由器 → B

A 发给路由器时：
源 MAC = A
目的 MAC = 路由器左接口
源 IP = A
目的 IP = B

路由器发给 B 时：
源 MAC = 路由器右接口
目的 MAC = B
源 IP = A
目的 IP = B
```

**易错点**

1. ARP 是 IP 到 MAC，不是域名到 IP。
2. ARP 请求广播，ARP 响应单播。
3. ARP 只在同一局域网/链路内解析下一跳 MAC。
4. 跨网段时解析的是默认网关 MAC，不是最终目的主机 MAC。
5. IP 地址端到端通常不变，MAC 地址逐跳变化。

## **Ethernet 以太网**

#### **1. 以太网帧格式**

常见字段：

```
前导码 + 目的 MAC + 源 MAC + 类型 + 数据 + CRC
```

|字段|作用|
|---|---|
|前导码|发送方和接收方时钟同步|
|目的 MAC|接收方链路层地址|
|源 MAC|发送方链路层地址|
|类型|指明上层协议，如 IP、ARP|
|数据|封装的网络层数据报|
|CRC/FCS|差错检测|

#### **2. 以太网服务特点**

经典以太网提供：

- 无连接服务
- 不可靠服务
- 接收方不会发送链路层 ACK
- 出错帧通常直接丢弃

注意：  
不可靠不等于不能检错，以太网有 CRC。

#### **3. 最小帧长**

传统 CSMA/CD 以太网要求最小帧长：

```
64 Byte
```

原因：

> 为了保证发送方在发送过程中能检测到最远端传播回来的碰撞信号。

如果帧太短，发送方可能已经发完了，才知道发生碰撞。

#### **4. 以太网和 CSMA/CD**

早期共享总线以太网使用 CSMA/CD。  
现代交换式以太网通常是全双工链路，基本不会发生碰撞，一般不再需要 CSMA/CD。

#### **5. 易错点**

1. 以太网帧用 MAC 地址，不用 IP 地址作为链路层目的地址。
2. CRC 用于差错检测，不负责纠错。
3. 以太网是不可靠服务，出错帧丢弃。
4. 最小帧长 64 Byte。
5. 现代交换式全双工以太网基本没有碰撞。

## **switches 交换机**。

**一句话说明**  
交换机解决的是：**在局域网中根据 MAC 地址把帧转发到正确端口，减少无效转发和碰撞。**

**1. 交换机工作层次**

交换机主要工作在：

```
数据链路层
```

依据：

```
MAC 地址
```

转发单位：

```
帧
```

**2. 交换机自学习**

交换机维护一张交换表：

```
MAC 地址 → 端口 → 时间
```

当交换机收到一个帧：

```
查看源 MAC
→ 记录“源 MAC 在这个输入端口”
→ 更新交换表
```

这叫自学习。

**3. 交换机转发规则**

收到帧后，看目的 MAC：

|情况|操作|
|---|---|
|目的 MAC 在交换表中，且对应端口不是输入端口|转发到对应端口|
|目的 MAC 在交换表中，且对应端口就是输入端口|过滤，不转发|
|目的 MAC 不在交换表中|洪泛，向除输入端口外所有端口发送|

关键词：

```
学习源地址，查目的地址
```

**4. 交换机特点**

- 即插即用
- 自学习
- 存储转发
- 每个端口是独立碰撞域
- 不隔离广播域，默认会转发广播帧
- 根据 MAC 地址转发，不看 IP 地址

**5. 交换机 vs 路由器**

|比较项|交换机|路由器|
|---|---|---|
|层次|数据链路层|网络层|
|转发单位|帧|IP 数据报/分组|
|依据|MAC 地址|IP 地址|
|表|交换表/MAC 表|路由表/转发表|
|作用范围|局域网内|不同网络之间|
|广播域|默认不隔离广播域|隔离广播域|

**易错点**

1. 交换机根据 MAC 地址转发，不是 IP 地址。
2. 交换机学习的是源 MAC，不是目的 MAC。
3. 目的 MAC 未知时是洪泛，不是丢弃。
4. 目的端口等于输入端口时过滤。
5. 交换机每个端口独立碰撞域，但默认不隔离广播域。
