# 完整性、视图、安全


## 完整性

### 1. 数据完整性

数据完整性是指：

```
数据库中数据的正确性、有效性和一致性。
```

常见三类：

| 类型      | 含义                     | 例子                      |
| ------- | ---------------------- | ----------------------- |
| 实体完整性   | 主键不能为空且唯一              | 学号不能重复，不能为空             |
| 参照完整性   | 外键要么为空，要么等于被引用表中的某个主键值 | SC.Sno 必须来自 Student.Sno |
| 用户定义完整性 | 根据业务规则定义的约束            | 成绩必须在 0 到 100 之间        |
### 2. 实体完整性

考试模板：

```
实体完整性要求关系中的主键属性不能为空且不能重复。
```

例子：

```
Student(Sno, Sname)
```

其中 `Sno` 是主键，则：

```
Sno 不能为 NULL，也不能重复。
```

---

### 3. 参照完整性

考试模板：

```
参照完整性要求外键的取值要么为空，要么等于被引用关系中某个主键值。
```

例子：

```
Student(Sno, Sname)
SC(Sno, Cno, Grade)
```

其中：

```
SC.Sno 是外键，引用 Student.Sno
```

则：

```
SC 中的 Sno 必须是 Student 中已经存在的 Sno。
```

---

### 4. 用户定义完整性

考试模板：

```
用户定义完整性是针对具体应用领域定义的数据约束。
```

例子：

```
Grade BETWEEN 0 AND 100
Age > 0
Sex IN ('男', '女')
```

## 视图 View

### 1.什么是视图？

视图是从一个或多个基本表导出的虚表。

```
视图本身通常不实际存储数据，只保存视图定义。
```

---

### 2. 创建视图

题目：

> 创建一个软件工程系学生视图。

```
CREATE VIEW SoftStudent AS
SELECT Sno, Sname, Dept
FROM Student
WHERE Dept = '软件工程';
```

---

### 3. 视图作用

考试模板：

```
视图可以简化用户操作，提高数据安全性，提供一定程度的数据独立性，并可以使用户以不同角度观察数据。
```


## 安全与授权

### GRANT 授权

```
GRANT SELECT
ON Student
TO User1;
```

意思：

```
把 Student 表的查询权限授予 User1。
```

---

### REVOKE 收回权限

```
REVOKE SELECT
ON Student
FROM User1;
```

意思：

```
从 User1 收回 Student 表的查询权限。
```
